## 确认失败的程序原因

本条精确时间：

| 事件 | Unix 纳秒 |
| --- | --- |
| 候选图像 Header | `1794470027395167000` |
| 逻辑裁切终点 | `1794470027406738758` |
| 同一图像的 bag 接收时间 | `1794470027427742691` |
| 停止请求 | `1794470028537132268` |

图像比逻辑终点早 11.571758 ms 拍摄，比逻辑终点晚 21.003933 ms 接收。旧 `recorded_header_exists` 把逻辑终点传给接收时间筛选，返回 `false`；改用真实录制接收范围可以找到完全相同的 Header。并非图像没有录到。

Episode 10、11 也复现该条件，接收时间分别晚于各自逻辑终点约 7.614、10.919 ms。它解释了这几条合法图像确认可能被拒绝的机制，不证明历史按钮是否实际点击；没有请求级操作日志可以还原全部用户操作。
