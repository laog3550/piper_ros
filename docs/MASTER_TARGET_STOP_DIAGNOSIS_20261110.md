# 主端目标提前停发与自动完成帧排查

## 现场结论

2026-11-10 的 `episode_000001` 录制到约 15.06 秒后自动结束。左主端四路原始目标帧 `0x155`、`0x156`、`0x157`、`0x159` 在约 10.80 秒同时停发，直到录制结束；从臂反馈和三路彩色相机仍持续写入。用户确认放入香蕉后会松开主臂、停止继续操作。这与主端目标停发时刻一致。现有 rosbag 无法证明主端内部停发的固件机制，但没有证据表明 rosbag、向量节点或相机使四路目标同时停发。

采集程序此前在固定时长到达时，直接把结束前最后一张相机图标为技能完成帧。此次该帧比最后有效主端目标晚约 4.26 秒，超出动作来源可核验区间，因此独立审计给出 `eligible_frame_count=0`。这属于自动完成标注与用户松开主臂的操作习惯不匹配；不能仅靠勾选“成功”改变训练资格。

## 程序修补与边界

固定时长自动停止保留。按操作员随后明确的采集约定，单臂技能在结束前出现持续 stale 时，程序识别其末尾有效到 stale 边界，再按原始 Header 选择该边界前最后一帧真实彩色图像，不按 stale 接收时刻选图，也不把中途恢复的停顿当作结束。边界及来源字段、无近时图像的拒绝条件见[末尾 stale 完成标记](STALE_COMPLETION_POLICY_20261110.md)。无可靠边界时沿用末帧与来源警告；原始 Header 和质量标志不改写。

该回溯只使标注时间更接近实际操作停止点，**不保证完成帧可用于训练**。本条数据在 10 FPS、30 ms 来源偏差、16 步窗口条件下，最后的有效连续片段只有 1 帧；新规则只读试算选中约 10.782 秒的相机帧，仍不在有效片段内。当前 Episode 仍需保留为诊断数据，不能作为已验收的 π0.5 训练样本。

下一轮采集应让主端目标持续发送到香蕉释放、从臂完成响应之后，再松开主臂；录制仍可等待固定时长自动结束。采集后检查自动完成帧是否落在连续且满足 16 步窗口的有效片段内。若操作时目标流仍出现 100–450 ms 间断，需检查主端松手/使能行为、CAN 源输出和向量节点 stale 判定，再决定是否调整采样或训练窗口，不能把缺失目标伪造成连续动作。
